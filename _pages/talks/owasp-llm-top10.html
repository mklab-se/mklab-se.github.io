MKLab · tech talk

The OWASP LLM Top 10

All ten risks of the 2026 edition, explained and animated: how LLM applications break, and how to build so it does not matter.

Space to begin

I · The stage

One application, many organs.

Every risk in this talk attacks the same body: a user, an application, a model, a context window that is half hidden, tools, a vector store, a training pipeline, and a meter counting the cost. Learn this stage once. For the next ten risks, watch where each attack lands.

II · The evidence

This order is earned.

For the first time, the 2026 edition tested opinion against reality: 7,714 real incidents, classified and compared with the community vote. They disagree in useful places. Prompt injection barely registers in the incident record, because teams defend it so hard, and it still holds first place. Misinformation was voted near the bottom, and the record pulled it up. The order you are about to see survived both tests.

III · What moved

Same ten. New priorities.

Excessive agency climbed to third, the most consequential move of the year, because that is where the damage lands. Unbounded consumption rose four places. Improper output handling fell to last. And system prompt leakage was reborn with a wider scope: hidden context exposure. Watch the migration.

LLM01 · Prompt injection

It is all one stream.

A model makes no architectural distinction between instructions and data: system prompt, user input, retrieved documents, tool output, everything is tokens on the same stream, and there is no equivalent of a parameterized query. Any text the model reads can steer it. That is why this stays number one: the surface is everywhere a model reads untrusted input, which is to say everywhere.

LLM01 · Prompt injection, part two

It does not have to come from the user.

An instruction can hide in a retrieved document, in an image whose pixels you see but whose tokens you do not, or in the model's own memory, where one poisoned write taints every later session. And when output drives tools, the blast radius is whatever the tools can reach. Defend accordingly: assume the model will be fooled, and gate what happens next.

LLM02 · Sensitive information disclosure

Every channel is an output.

Secrets do not only leave through the answer. Tool arguments, reasoning traces, logs, telemetry, embeddings, even response timing are disclosure surfaces, and a model can also memorize training data and repeat it back. Treat every channel like the answer: classified, redacted, and watched, especially the ones nobody reads.

LLM03 · Excessive agency

The reach exceeds the need.

Give a model tools and it becomes able to act. Excessive agency is what happens when the granted reach is wider than the task: too many tools, too much permission, too much autonomy. Then any malfunction, a hallucination, an injection, a compromised peer agent, becomes a damaging action. The year's biggest climber, up to third, because agentic deployments are where the damage now lands.

LLM03 · Excessive agency, part two

Shrink the reach. Keep the human.

The defense is not a smarter model. It is minimal agency: only the tools the task needs, the narrowest permissions that work, and no high-impact action without a human in the loop. The triggers will keep firing. With the reach scoped, they hit walls instead of systems.

LLM04 · Supply chain

Is the model what it claims to be?

LLM applications are assembled from other people's work: pre-trained models, datasets, adapters, conversion pipelines. Each is an attack surface, and a promoted artifact is not always what it says it is. Provenance, signatures and pinned versions are the difference between a dependency and a stowaway.

LLM05 · Data and model poisoning

It learns the wrong thing, quietly.

Poisoning targets the learning process itself: tampered training data, a subverted fine-tune, a corrupted embedding. The model still looks fine. The backdoor waits for its trigger. And unlike a code bug, you cannot patch it: recovery means revalidating data, retraining, or replacing the model.

LLM06 · Unbounded consumption

Cheap to ask. Expensive to answer.

Cost asymmetry defines this risk: an attacker triggers disproportionately expensive computation at almost no cost to themselves, through crafted prompts, stolen keys, or agent loops that amplify one request into cascades. Rate limiting is not enough anymore. You need token-aware cost controls, hard caps, and circuit breakers that trip mid-burn.

LLM07 · Misinformation

Fluent is not true.

When a confident, wrong answer drives a decision or a tool call, a wrong answer becomes a wrong action. Practitioners voted this risk near the bottom. The incident record put it near the top, the widest gap in the direction that hurts. Grounding, verification and human judgment belong between the answer and the act.

LLM08 · Hidden context exposure

Assume it is discoverable.

Half of the context window was never meant for the user: system instructions, policies, tool schemas, operating rules. It can be extracted, inferred or reconstructed, and the 2026 edition widens the old system prompt leakage into exactly this. The defense is a posture: nothing secret in the context, and nothing that breaks when it is read out.

LLM09 · Vector and embedding weaknesses

Geometry can be attacked.

Wherever similarity search decides what the model sees, the embedding space is part of your trust boundary, and its geometry can be turned against you. Poisoning makes the system wrong. Inversion makes it leak. Jamming makes it silent. Broken access control makes it indiscriminate. Four failures, one space.

LLM10 · Improper output handling

Treat the output like user input.

Model output flows into browsers, shells and databases, and whoever steers the model steers that output. Passed along raw, it becomes cross-site scripting, request forgery, or remote code execution downstream. The fix is old wisdom in a new place: validate and sanitize before anything downstream touches it.

IV · The boundary

When the model becomes an actor.

This list owns the risk while the model is a component inside your application. The moment it gains tools, memory between sessions, and consequences it sets in motion, the risk moves to the OWASP Agentic Top 10. Many real incidents sit exactly on that line. Know which side of it you are building on, and read accordingly.

V · The posture

Build for the day it is fooled.

The 2026 edition opens with its own best advice: stop trying to build a model that cannot be fooled, and build the system around it so that when the model is fooled, and it will be, nothing important breaks. Work all ten. Start at the top. That posture is the whole talk in one sentence.
